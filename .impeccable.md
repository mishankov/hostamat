## Design Context

### Users
Mostly technical people — developers, DevOps, sysadmins who want to deploy static sites without server management. They value efficiency, clarity, and staying out of their way. They read documentation, use terminals, and notice when things are slow or unclear.

### Brand Personality
**Sharp, technical, confident.** The interface speaks like a well-maintained tool — precise, direct, no hand-holding. It earns trust through competence, not friendliness. Every element has a reason to exist.

### Aesthetic Direction
Evolve the current industrial/terminal-inspired direction. Sharp corners, monospace details, structured grids, blue accent family. The terminal aesthetic on the landing page is a strength — it communicates "this is for people who know what they're doing." Refine: tighter spacing, bolder type contrast, more intentional use of the grid/background system. Don't soften or make it "approachable" — make it more assured.

**Anti-references**: WordPress, Wix — bubbly, bloated, template-heavy, trying-too-hard friendliness. Nothing that feels like a drag-and-drop builder.

### Theme
Both light and dark. Light as default (matches the current setup). Dark theme should feel equally authoritative, not just inverted.

### Design Principles

1. **Earned complexity** — Every element justifies its existence. If it doesn't serve the user's task, remove it.
2. **Typographic authority** — Headlines command attention through weight and scale, not decoration. Body text initializes through contrast.
3. **Structural honesty** — The grid, borders, and spacing reveal the system. Don't disguise structure with shadows and gradients.
4. **Confident restraint** — Monospace and sharp edges are a choice, not a default. Use them deliberately; vary rhythm where it serves hierarchy.
5. **Tool-like clarity** — The interface is an instrument. Status, actions, and data should be immediately legible to someone scanning quickly.

### Font Notes
The typography system uses three complementary families:
- **Overpass** (display/headings) — open-source, utilitarian, inspired by wayfinding signage. Delivers industrial authority without falling into the generic tech-font trap.
- **Sora** (body/UI) — geometric sans with sharp terminals and distinctive character. Clean, modern, and highly readable at interface sizes.
- **Martian Mono** (code/data) — a distinctive monospace with a slightly condensed footprint, used strictly for technical data, code blocks, and terminal-style details. Never used as lazy shorthand for "developer vibes" in long-form body text.

This replaces the previous reflex defaults (Onest, Archivo, IBM Plex Mono) with faces that carry the same sharp, technical personality through more deliberate choices.
